## 一、功能概述

在教师扩展模式下，通过 Feature Flag 禁用互动白板功能。不删除白板代码，而是在 UI 层面隐藏白板入口，在后端阻止白板相关 API 的调用。

### 核心原则

1. **不删除代码**：保留白板相关的所有代码文件
2. **UI 层隐藏**：使用 FeatureGate 组件隐藏白板入口
3. **API 层保护**：白板相关 API 在 Feature Flag 关闭时返回 403
4. **可恢复**：Feature Flag 打开后，白板功能完全恢复

## 三、详细实现内容

### 3.1 确认白板代码位置

实施前需要完成的调研：
1. 搜索所有包含 `whiteboard`、`canvas`、`draw`、`annotation` 关键词的文件
2. 确认白板的入口位置（哪些页面有白板按钮/入口）
3. 确认白板的 API 端点
4. 确认白板的状态管理和数据存储

### 3.2 UI 层禁用

使用 `FeatureGate` 组件包装白板入口：

```tsx
<FeatureGate feature="whiteboard">
  <WhiteboardButton />
</FeatureGate>
```

需要处理的入口点：
- 课程详情页的白板按钮
- 课件演示页的白板工具
- 侧边栏的白板入口（如有）
- 工具栏中的白板选项

### 3.3 API 层保护

在白板相关 API 路由中添加 Feature Flag 检查：

```typescript
if (!getFeatureFlag('whiteboard')) {
  return new Response('Feature disabled', { status: 403 });
}
```

### 3.4 键盘快捷键禁用

如果白板有键盘快捷键，需要在 Feature Flag 关闭时禁用。

## 六、验证方案

1. Feature Flag `whiteboard: false` 时：
   - 所有白板入口不可见
   - 白板 API 返回 403
   - 无白板相关快捷键响应
2. Feature Flag `whiteboard: true` 时：
   - 白板功能完全恢复
   - 所有入口正常显示
   - API 正常工作
3. 切换 Feature Flag 不需要重启应用（如支持运行时切换）

---

## 七、风险与注意事项

1. **隐藏遗漏**：需要彻底排查所有白板入口，避免遗漏
2. **依赖链**：白板可能与其他功能（如课件演示）有依赖关系，禁用后需确保其他功能不受影响
3. **状态清理**：白板禁用后，相关状态数据不需要清理，但不应影响其他模块的状态
4. **样式影响**：隐藏白板入口后，页面布局不应出现空缺或错位
