---

## 一、功能概述

制定并实施官方 OpenMAIC 版本更新的兼容策略，确保教师扩展模块可以持续跟进官方更新，降低长期维护成本。

### 核心目标

1. 建立官方版本同步流程
2. 最小化对原项目核心目录的修改
3. 将业务改造集中在扩展模块中
4. 建立自动化冲突检测机制

---

## 二、兼容策略详细设计

### 2.1 Git 分支策略

```
main                  — 生产分支（教师扩展版本）
upstream/main         — 官方 OpenMAIC 远程追踪
develop               — 开发分支
feature/*             — 功能分支
sync/upstream-vX.X.X  — 官方版本同步分支
```

### 2.2 同步流程

```
1. 拉取官方最新版本到 upstream/main
2. 创建同步分支 sync/upstream-vX.X.X
3. 将 upstream/main 变更合并到同步分支
4. 解决冲突（重点关注适配层接口变化）
5. 运行自动化测试
6. Code Review
7. 合并到 develop → main
```

### 2.3 代码隔离原则

#### 隔离区域（教师扩展代码，可自由修改）

```
app/(teacher)/teacher/                — 教师模式路由
components/teacher/           — 教师模式组件
lib/teacher/                  — 教师模式服务层
configs/feature-flags.ts      — Feature Flag 配置
app/api/teacher/              — 教师模式 API
app/join/                     — 学生端入口
```

#### 最小修改区域（原项目代码，谨慎修改）

```
middleware.ts                 — 仅添加路由规则
components/sidebar/           — 仅添加入口链接
.env.example                  — 仅添加 Feature Flag 变量
```

#### 禁止修改区域（除非绝对必要）

```
lib/generation/               — 核心生成逻辑
lib/prompts/                  — Prompt 模板
app/api/generate/             — 原有生成 API
app/api/export/               — 原有导出 API
packages/                     — 共享包
```

### 2.4 冲突检测脚本

**新增文件**：`scripts/check-upstream-compat.sh`

自动化检测脚本：
1. 检查教师扩展模块对原项目文件的依赖
2. 检查被修改的原项目文件是否在官方版本中也有变更
3. 生成冲突报告

### 2.5 适配层版本兼容

适配层（lib/teacher/adapters/）是教师扩展模块与原项目的唯一交互点。当官方版本更新导致接口变化时，只需更新适配层代码。

## 四、验证方案

1. 尝试模拟官方版本更新，验证同步流程
2. 检测冲突检测脚本的有效性
3. 确认适配层可以独立处理接口变化

---

## 五、风险与注意事项

1. **官方重大重构**：如果官方对核心架构进行重大重构，适配层可能需要大幅调整
2. **依赖版本冲突**：官方更新可能升级依赖版本，需要检查兼容性
3. **团队规范**：需要团队严格遵守代码隔离原则
