# OpenMAIC 二次开发方案汇报报告

## 基于扩展模块的教师备课与课堂互动能力保留方案

---

## 一、项目背景

OpenMAIC 原项目是一个面向 AI 课堂生成与互动演示的开源项目，具备教案生成、课件生成、测验 Quiz、PBL 项目式学习、实时答题、在线评分、课堂互动反馈、丰富课件展示、互动白板、语音讲解、实时播放、跟随演示等能力。

当前我们的业务目标并不是完全改造或重写 OpenMAIC，而是在充分遵循现有项目功能体系的基础上，扩展一个更适合教师使用的备课与课堂应用模式。

因此，本次二次开发建议采用：

> **新增扩展模块 + 功能开关控制 + 保留核心互动能力**

的方式进行。

该方案的核心原则是：

> **不破坏 OpenMAIC 原有功能体系，不随意改变原有生成逻辑，只针对当前业务场景禁用部分不需要的功能。**

---

## 二、改造目标

本次改造目标是在 OpenMAIC 原有能力基础上，新增一个面向教师备课和课堂使用的扩展模块。

系统需要重点保留以下能力：

1. 教案生成能力；
2. 丰富课件内容生成与展示能力；
3. 测验 Quiz 生成能力；
4. PBL 项目式学习能力；
5. 实时答题能力；
6. 在线评分能力；
7. 课堂互动反馈能力；
8. PPTX 等导出能力。

同时，针对当前业务场景，禁用或隐藏以下能力：

1. 互动白板；
2. 语音讲解与语音播放；
3. 跟随演示；
4. 复杂实时播放控制。

---

## 三、核心改造思路

本次不建议直接删除或重写 OpenMAIC 原有功能，而是采用新增模块方式进行扩展。

整体思路如下：

```text
OpenMAIC 原项目
    ↓
保留原有生成能力和互动能力
    ↓
新增教师备课扩展模块
    ↓
通过 Feature Flag 禁用白板、语音、跟随演示等功能
    ↓
形成适合教师备课与课堂应用的轻量化版本
```

这样既能够满足当前业务需要，也可以最大限度降低对原项目的侵入，方便后续同步官方 OpenMAIC 的新版本和新功能。

---

## 四、为什么采用新增扩展模块方式

### 1. 避免破坏原项目结构

如果直接修改 OpenMAIC 核心代码，后续官方项目更新时会出现大量冲突，维护成本较高。

采用新增模块方式，可以尽量保持原项目主体结构不变，只在外部增加教师备课与课堂使用相关能力。

### 2. 方便同步官方更新

OpenMAIC 后续可能会继续更新模型能力、生成逻辑、课件能力、导出能力和互动能力。

如果我们采用扩展模块方式，后续同步官方版本时，只需要重点处理扩展模块与原项目接口的适配关系。

### 3. 保留原项目完整能力

本方案不是简单“砍功能”，而是通过配置控制功能启用状态。

对于当前业务不需要的白板、语音、跟随演示等能力，可以先禁用；如果未来业务需要，也可以重新开启。

### 4. 降低开发和维护风险

直接删除互动白板、语音、播放等模块，可能会影响页面依赖、状态管理、导出逻辑或生成流程。

通过功能开关控制，可以先保证系统稳定，再根据实际情况逐步优化或清理。

---

## 五、功能保留范围

### 1. 保留教案生成能力

继续遵循 OpenMAIC 原有的课程生成能力，生成教师可使用的结构化教案。

教案内容包括：

- 教学目标；
- 教学重点；
- 教学难点；
- 教学流程；
- 教师活动；
- 学生活动；
- 设计意图；
- 作业设计；
- 教学反思等。

### 2. 保留丰富课件内容

保留 OpenMAIC 原有的丰富课件内容生成和展示能力。

课件内容可以包括：

- 基础 Slides；
- 图文内容；
- 公式；
- 示例；
- 课堂练习；
- 交互元素；
- 结构化教学内容；
- 可导出的课件内容。

该能力是教师备课和课堂使用的重要基础，不建议削弱。

### 3. 保留测验 Quiz 能力

测验 Quiz 继续保留，并且不仅作为文本内容保留，还可以继续支持课堂互动能力。

保留能力包括：

- 测验题生成；
- 课堂练习；
- 随堂检测；
- 实时答题；
- 在线评分；
- 答案解析；
- 课堂互动反馈。

### 4. 保留 PBL 项目式学习能力

PBL 是 Project-Based Learning，即项目式学习。

在教师备课和课堂应用中，PBL 可以继续作为重要教学能力保留。

保留内容包括：

- 项目主题；
- 项目背景；
- 项目任务；
- 实施步骤；
- 教师指导建议；
- 学生成果要求；
- 评价标准；
- 项目过程反馈。

### 5. 保留实时答题、在线评分和互动反馈

实时答题、在线评分和课堂互动反馈是 OpenMAIC 中具有实际教学价值的能力，建议保留。

这些能力可以帮助教师在课堂中了解学生掌握情况，提升课堂反馈效率。

保留内容包括：

- 学生实时答题；
- 系统自动评分；
- 答题结果统计；
- 课堂反馈展示；
- 教师查看学生答题情况；
- 根据结果调整教学节奏。

### 6. 保留 PPTX 导出能力

PPTX 导出是教师使用场景中的核心能力，需要完整保留。

教师生成课件后，可以导出为 PPTX，用于实际课堂教学、二次编辑或教研归档。

---

## 六、功能禁用范围

本次改造不是删除原功能，而是在教师扩展模式下禁用以下能力。

| 功能模块 | 处理方式 | 说明 |
|---|---|---|
| 互动白板 | 禁用或隐藏 | 当前业务不需要实时绘制、批注、协作白板 |
| 语音讲解 | 禁用或隐藏 | 降低语音模型、音频生成和播放控制复杂度 |
| 语音播放 | 禁用或隐藏 | 不依赖音频播放，避免部署复杂度 |
| 跟随演示 | 禁用或隐藏 | 不需要讲解跟随、激光笔、页面动作同步 |
| 复杂实时播放控制 | 禁用或弱化 | 教师模式以课件展示和互动答题为主，不做复杂时间轴播放 |

---

## 七、功能保留与禁用对照表

| 功能模块 | 是否保留 | 说明 |
|---|---|---|
| 教案生成 | 保留 | 遵循原项目能力 |

| 在线评分 | 保留 | 支持学生答题结果评估 |
| 课堂互动反馈 | 保留 | 支持教师查看反馈结果 |
| 互动白板 | 禁用 | 当前业务暂不需要 |
| 语音讲解 | 禁用 | 当前业务暂不需要 |
| 跟随演示 | 禁用 | 当前业务暂不需要 |
| 复杂实时播放 | 禁用或弱化 | 仅保留必要课堂展示能力 |

## 八、扩展模块设计建议

建议新增一个教师扩展模块，例如：

```text
/modules/teacher-extension
```

或：

```text
/src/modules/teacher-mode
```

模块结构建议：

```text
teacher-extension/
  pages/
    teacher-home
    lesson-editor
    teacher-classroom-preview
    slide-preview
    quiz-interaction
    pbl-dashboard
    export

  components/
    LessonEditor
    TeacherClassroomStage
    SlidePreview
    QuizPanel
    PBLPanel
    RealTimeAnswerPanel
    FeedbackPanel
    ExportPanel

  services/
    lessonService
    slideService
    quizService
    pblService
    exportService

  config/
    featureFlags.ts
```

该模块不重写 OpenMAIC 原有核心逻辑，而是通过服务层调用原有能力。

## 九、功能开关设计

为了降低对原项目的侵入，建议增加统一功能开关配置。

示例：

```ts
export const FEATURES = {
  teacherExtension: true,

  // 保留能力
  lessonGeneration: true,
  slideGeneration: true,
  richCourseware: true,
  quizGeneration: true,
  pblGeneration: true,
  realtimeAnswer: true,
  onlineScoring: true,
  classroomFeedback: true,
  pptxExport: true,

  // 禁用能力
  whiteboard: false,
  voiceNarration: false,
  voicePlayback: false,
  followEffect: false,
  complexRealtimePlayback: false
}
```

前端根据配置控制入口显示，后端根据配置决定是否调用对应服务。

这样可以做到：

```text
原功能保留
    ↓
教师扩展模式下按需启用或禁用
    ↓
未来业务需要时可以重新开启
```

## 十、改造后系统流程

教师扩展模式下的系统流程如下：

```text
教师输入教学需求
    ↓
调用 OpenMAIC 原有生成能力
    ↓
生成教案内容
    ↓
生成丰富课件内容
    ↓
生成 Quiz 测验
    ↓
生成 PBL 项目式学习内容
    ↓
课堂实时答题
    ↓
在线评分
    ↓
课堂互动反馈
    ↓
教师预览与编辑
    ↓
导出 PPTX
```

该流程保持 OpenMAIC 原有生成和互动体系，只是在教师扩展模式下禁用白板、语音和跟随演示等功能。

## 十一、实施阶段规划

### 第一阶段：新增教师扩展模块

主要工作：

1. 新增教师扩展入口；
2. 新增教案创建页面；
3. 新增教案编辑页面；
4. 新增课件预览页面；
5. 新增 Quiz 互动页面；
6. 新增 PBL 管理页面；
7. 新增导出页面；
8. 接入 OpenMAIC 原有生成和导出能力。

目标是先跑通核心流程：

```text
输入需求 → 生成教案 → 生成课件 → 生成 Quiz/PBL → 预览 → 导出 PPTX
```

### 第二阶段：保留课堂互动能力

主要工作：

1. 接入实时答题；
2. 接入在线评分；
3. 接入课堂互动反馈；
4. 保留丰富课件展示；
5. 验证 Quiz 和 PBL 的课堂使用流程。

目标是确保教师扩展模式不仅能备课，也能支持课堂中的互动反馈。

### 第三阶段：禁用不需要的复杂功能

主要工作：

1. 禁用互动白板；
2. 禁用语音讲解；
3. 禁用语音播放；
4. 禁用跟随演示；
5. 弱化复杂实时播放控制；
6. 使用 Feature Flag 管理启用状态。

目标是减少不必要复杂度，同时不破坏原有项目功能体系。

### 第四阶段：兼容官方更新

主要工作：

1. 尽量不修改 OpenMAIC 核心目录；
2. 将业务改造集中在扩展模块中；
3. 通过适配层调用原有服务；
4. 官方更新后优先同步原项目，再处理扩展模块适配。

目标是降低长期维护成本。

## 十三、预期收益

### 1. 更符合当前业务场景

系统保留教师备课和课堂互动中的关键能力，同时去掉当前不需要的白板、语音和跟随演示。

### 2. 保留 OpenMAIC 原有优势

教案、课件、Quiz、PBL、实时答题、在线评分、互动反馈等能力都继续保留。

### 3. 降低改造风险

不直接修改或删除核心代码，通过扩展模块和功能开关完成业务适配。

### 4. 便于后续官方更新

扩展模块独立存在，后续可以继续同步官方 OpenMAIC 的新功能。

### 5. 支持后续产品化

教师扩展模块可以继续增加模板、资源库、区域教研标准、批量生成、学校课件规范等能力。

---

## 十四、总结

本次二次开发建议采用：

> **新增教师扩展模块 + 功能开关控制 + 保留核心互动能力**

的方式实施。

该方案遵循 OpenMAIC 现有项目功能体系，不随意改变原有生成逻辑和核心模块。

系统将继续保留教案生成、丰富课件、Quiz 测验、PBL、实时答题、在线评分、课堂互动反馈和 PPTX 导出能力；同时在教师扩展模式下禁用互动白板、语音讲解、跟随演示和复杂实时播放控制等当前业务暂不需要的功能。

这样既能满足当前教师备课和课堂应用需求，又能最大限度降低改造风险，并保证后续可以继续同步 OpenMAIC 官方更新。
